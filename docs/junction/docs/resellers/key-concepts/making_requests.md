# Making Requests

## Request Headers

### Access Token (Required)

Remember to send your access token in the *Authorization* request header using the "Bearer" authentication scheme.

`Authorization: Bearer <YOUR_ACCESS_TOKEN>`

##### Example:

```shell
curl -X GET 'https://api.junction.dev/places/types' \
--header 'Authorization: Bearer <YOUR_ACCESS_TOKEN>'
```

Example of an access token: `eyJhbGciOiJSUzI1NiIsImtp...`

[<small>Forgot where you get your Access Token?</small>](/docs/resellers/getting-started/account_setup)

### MIME types (Required)

All responses from the API follow the [**JSON:API**](https://jsonapi.org/) standard. We need to ensure our response is returned as a JSON format.

An *Accept* header is required with every request:

`Accept: application/vnd.api+json`

##### Example:

```shell
curl -X GET 'https://api.junction.dev/places/types' \
--header 'Accept: application/vnd.api+json' \
--header 'Authorization: Bearer <YOUR_ACCESS_TOKEN>'
```

Furthermore, all request bodies sent to the API should be in JSON format.

A *Content-Type* header is required whenever you're sending a request body (i.e. for POST and PUT requests):

`Content-Type: application/vnd.api+json`

##### Example:

```shell
curl -X POST 'https://api.junction.dev/trip-candidates/searches' \
--header 'Content-Type: application/vnd.api+json' \
--header 'Authorization: Bearer <YOUR_ACCESS_TOKEN>' \
```

### Session Token (Optional)

Some endpoints will benefit from using a session token.

This token should be a random 32-character long string generated by ***you***, and should be the **same** throughout a booking flow, but different for each *new* booking flow.

It will be added to the header like this:

`Session-Token: <YOUR_SESSION_TOKEN>`

##### Example:

```shell
curl -X POST 'https://api.junction.dev/trip-candidates/searches' \
--header 'Content-Type: application/vnd.api+json' \
--header 'Authorization: Bearer <YOUR_ACCESS_TOKEN>' \
--header 'Session-Token: <YOUR_SESSION_TOKEN>' \
```

## Request Body

### Session Token (Optional)

This session token is very similar to the one mentioned [**above**](#session-token-optional). However the difference is that this is to be used to save your searches within the same session.
*WARNING: PLEASE REWORD EXPLANATION

This token should be a random 32-character long string generated by ***you***, and should be the **same** throughout a booking flow, but different for each *new* booking flow.

##### Example:

```shell
curl -X POST 'https://api.junction.dev/trip-candidates/searches' \
--header 'Content-Type: application/vnd.api+json' \
--header 'Authorization: Bearer <YOUR_ACCESS_TOKEN>' \
--data '<YOUR_JSON_DATA>' \
```

##### Request Body Example:

```json
{
  "data": {
    "type": "trip-candidate-searches",
    "attributes": {
      "sessionToken": <SESSION_TOKEN>,
      "criteria": [],
      "passengers": []
    },
  }
}
```

## Query Parameters

Some endpoints allow optional query paramters.

You add the following syntax to the end of your URL: `?KEY_WORD=VALUE`

Example:

```
https://api.junction.dev/places?page[limit]=2
```

`GET /places` has an optional query parameter `page[limit]` which can filter the response to limit results to the given value `2`.

---

### Pagination

A common query parameter you will come across is `page[cursor]`.

When data is too large to be returned as a whole, it will be chunked and the first section returned with a link to the next.

Example of link in response:

```json
{
    "links": {
        "next": "https://api.junction.dev/places?page%5Bcursor%5D=ABCDEFG"
    }
}
```

The value in `next` is the next page of your search. Simply, make a request again and apply this to the `page[cursor]` pagination query parameter.

Example:

```
https://api.junction.dev/places?page%5Bcursor%5D=ABCDEFG
```

`GET /places` has an optional query parameter `page[limit]` which can filter the response to limit results to the given value `2`.

## Polling

Most endpoints are asynchronous, which means that after `POST`ing a request (for example a trip search), the `status` attribute in the response body will likely be `pending` as the search is not yet finished.

You will have to regularly poll for the results until the status of the search is marked as `completed`.

##### Response Body Example:

```json
{
    "data": {
        "id": "00011aab-2b3c-4567-c789-ddde1e0ee123d",
        "type": "trip-candidate-searches",
        "attributes": {
            "passengers": [],
            "criteria": [],
            "expiresAt": "2020-01-30T12:00:42.136924Z",
            "status": "pending"  // <-- Keep polling until 'completed'
        },
        "links": {
            "self": "https://api.junction.dev/trip-candidates/searches/6211fd15-b656-4594-9603-cef75bdac261"
        }
    }
}
```
